Emergency LocatorWhen a user opens the app after a crash:* the app detects current location* shows **nearest trauma centres*** shows **nearest ambulance services*** shows **nearest police station*** shows **nearest towing / rescue services*** shows **nearest puncture repair / mechanic shops**### B. SOS BroadcastThe user can send:* GPS location* time of incident* vehicle type* injury severity hint* prefilled message to emergency contacts### C. Offline Rescue ModeIf the network is weak:* show cached emergency contacts* show nearest saved services* allow call via stored numbers* store incident data locally and sync later### D. Road Hazard IntelligenceA secondary module can show:* potholes* road damage* sharp turns* high-risk accident zones* one-way roads* caution zones* safe routesThis is useful, but it should support the emergency mission rather than replace it.### E. Optional Vehicle AssistanceFor broken-down vehicles:* connect to nearby mechanics* towing providers* puncture repair* nearby showroom / service centre info\---## 6\) What to remove or reposition### Remove from the main pitch ❌* “scan number plate to identify the culprit”* “track speed of the vehicle”* “track overall condition of vehicle”### Reposition as optional features ✅* **Incident documentation*** **Vehicle profile for emergency responders*** **Crash evidence storage*** **Driver-side safety insights**This keeps your project relevant and avoids looking like a surveillance or fault-detection system.\---## 7\) Why this revised idea is strongerYour revised version will be stronger because it:* solves the **exact hackathon problem*** is more **practical*** is more likely to score well on **reliability*** supports **offline use*** supports **multiple countries*** offers clear **innovation without drifting away from the brief**\---## 8\) Core user flow1.
